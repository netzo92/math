# Pasta endomorphism: known structural attack discount

## Question and model

Can the cube-root endomorphism of a Pasta-like curve shrink a discrete-log search space, and would that be a new Zcash weakness? This iteration checks the group action on **tiny synthetic curves** `y² = x³ + 5` over prime fields `p < 1000`. It counts orbit classes, not attack time. It uses neither real keys nor production curves.

The [Pasta implementation](https://github.com/zcash/pasta_curves#curve-descriptions) specifies Pallas and Vesta with this curve equation over much larger fields. The [Halo 2 curve background](https://zcash.github.io/halo2/background/curves.html) describes the endomorphism `(x,y) ↦ (ζx,y)` for a nontrivial cube root `ζ` in the base field. [Orchard keys](https://zcash.github.io/orchard/design/keys.html) use Pallas. These sources motivate the toy model; this experiment does not establish protocol compatibility or security.

## Derivation

For `a=0` and `ζ³=1`, if `y²=x³+b`, then `y²=(ζx)³+b`; the map preserves the curve. It commutes with group addition. On a cyclic prime-order subgroup generated by `G`, its image is `[λ]G` for some `λ`, and applying the map three times gives `λ³=1 (mod q)`. For nontrivial `λ`, the automorphism and negation give up to six representatives `±[λ^i]P`, `i∈{0,1,2}`, per nonidentity point. On the toy subgroups below, every such orbit has exactly six points and there are `(q−1)/6` nonzero orbits plus identity.

An idealized collision search on six-point classes has about one-sixth as many states; its *heuristic* square-root collision scale is therefore smaller by roughly `√6`. This is a constant-factor observation, **not** an algorithm implementation, measured speedup, change to the square-root exponent, or full operation-cost model. Canonicalization and walk design can create fruitless cycles; see the [automorphism attack research](https://www.iacr.org/archive/pkc2014/83830154/83830154.pdf) and [negation-map analysis](https://cr.yp.to/elliptic/negation-20110102.pdf). The [Ironwood security-model discussion](https://zcash.github.io/ironwood/formal-verification/security-models.html#the-algebraic-adversary-restriction) already incorporates the known automorphism-class rho attack in its approximately `2^126` Vesta attack-cost discussion. This is prior art, not a newly discovered weakness.

## Reproduce and result

Run `python3 -m experiments.toy_endomorphism` and `python3 -m unittest discover -s tests` from the repo root. Python 3.11+; no dependencies. The implementation checks every subgroup element against scalar multiplication, verifies that applying the endomorphism three times returns the original point, and checks each six-point orbit. These are correctness checks, not elapsed-time benchmarks.

The structural hypothesis is **confirmed only in these toy groups** and already known for Pasta. It does not imply that Zcash keys or funds are compromised. No sub-square-root attack, exploit, or novel security finding emerged.

## Next question

Can a precisely specified non-generic property of the deployed Pallas/Vesta representations yield more than this **already-accounted-for** constant-factor reduction? First survey known attacks and their assumptions; then specify a falsifiable cost target and an independently checked toy analogue. An alternative defender track is to benchmark a named Halo 2 multi-scalar multiplication call with operation counts and correctness vectors.
